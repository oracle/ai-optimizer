## v2.5.1 — 16 November 2026

This release makes Oracle AI Database a required service, updates Testbed evaluation and MCP support, and improves vector store refresh workflows.

### Upgrade considerations

- Python 3.12, 3.13, and 3.14 are supported, excluding Python 3.14.1. Python 3.11 is no longer supported.
- The Server requires a complete Oracle AI Database configuration and a successful connection at startup. Standalone deployments use the `AIO_DB_USERNAME`, `AIO_DB_PASSWORD`, and `AIO_DB_DSN` environment variables. The local client and all-in-one container provide a setup page when these values are absent.
- The required database connection uses the reserved `CORE` alias and is controlled by the deployment configuration. Helm deployments must configure `server.database`.
- External MCP clients must support the sessionless MCP `2026-07-28` protocol and Streamable HTTP transport.

### Highlights

- **Testbed evaluation:** Test set generation and evaluation now use Giskard v3. Test sets and evaluation reports are stored in Oracle AI Database, including previous reports that can be reviewed from the client.
- **MCP:** MCP support has been updated to FastMCP v4 with deterministic tool catalogs, configurable private cache hints, and current wire-format conventions. Vector Search requests can select a specific vector store with the `collection_alias` tool argument.
- **Split and Embed:** Re-uploading a local file replaces its existing chunks after the new content is embedded. Failed or empty replacements preserve the previous document.
- **Deployment:** The Helm chart includes expanded database modes and examples, can generate and retain the Streamlit signed-cookie secret, and provides additional high-availability, ingress TLS, and OCI deployment overlays.
- **Dependencies:** Application, documentation, and build dependencies have been refreshed.

For the complete set of changes, see [`v2.5.0...v2.5.1`](https://github.com/oracle/ai-optimizer/compare/v2.5.0...v2.5.1).

## v2.5.0 — 18 September 2026

This release removes the matplotlib dependency, updates Testbed report rendering, and improves OCI GenAI streaming compatibility.

### Highlights

- **Testbed reporting:** The overall correctness gauge now uses scalable SVG rendering. Q&A generation, evaluation, and report exports operate without matplotlib.
- **OCI GenAI streaming:** Improved compatibility with compressed streaming responses while preserving custom request headers.
- **Dependencies:** Refreshed application dependencies, including the OCI SDK, LangChain Core, PyTorch, and Transformers, along with development tools.

For the complete set of changes, see [`v2.4.1...v2.5.0`](https://github.com/oracle/ai-optimizer/compare/v2.4.1...v2.5.0).

## v2.4.1 — 20 August 2026

This maintenance release improves the Oracle Backend as a Service (OBaaS) deployment, the mortgage demonstration, and client configuration workflows.

### Highlights

- **Mortgage demonstration:** The mortgage corpus, prompts, and Deep Data Security walkthrough have been updated to reflect the current sample data and policy flow.
- **Client reliability:** Testbed requests now remain disabled while they run, and clearing a Deep Data Security connect-as selection allows additional time for the server to rebuild its SQLcl connection store.
- **Settings import:** Updating saved prompts through settings import now refreshes cached chat sessions so they use the updated prompts.
- **OBaaS deployment:** When AI Optimizer is installed as an [Oracle Backend as a Service](https://oracle.github.io/microservices-backend/obaas/) subchart and shares an Autonomous Database Shared instance, it can reuse the wallet resources managed by Oracle Database Base Service.

For the complete set of changes, see [`v2.4.0...v2.4.1`](https://github.com/oracle/ai-optimizer/compare/v2.4.0...v2.4.1).

## v2.4.0 — 10 August 2026

This release adds [Oracle Deep Data Security](./client/tools/dds.mdx) support, expands model and embedding workflows, and refreshes the installation, deployment, and documentation experience.

### Upgrade considerations

- macOS x86_64 is no longer a supported installation target. macOS support is limited to Apple silicon (`arm64`).
- Existing bare-metal environments should be recreated with `uv sync --all-extras` before starting the application with `uv run python src/entrypoint.py client`.
- The model configuration API now reports runtime availability through `status` instead of the previous `usable` Boolean. Possible values are `available`, `unreachable`, `not_pulled`, and `no_key`.
- Helm service types are limited to `ClusterIP`, `NodePort`, and `LoadBalancer`.
 
### Highlights

- **Oracle Deep Data Security:** Create and manage data roles, end users, and data grants from the client. Vector Search and NL2SQL can connect as a selected end user so that database-enforced row- and column-level access applies to tool results.
- **Model configuration:** Model availability now distinguishes between available, unreachable, missing-key, and not-yet-pulled states. Enabled model endpoints are rechecked in the background, allowing a provider such as Ollama to recover without restarting the AI Optimizer. Ollama discovery, model pulling, duplicate handling, and configuration persistence have also been improved.
- **New local model defaults:** `granite4.1:8b` and `mxbai-embed-large` are included as disabled Ollama configurations, and the Helm deployment pulls them by default when its bundled Ollama service is enabled.
- **Split and Embed:** Local files and OCI Object Storage objects can be grouped into one vector store per filename. SQL query results can also be used as a document source. Embedding-job persistence, cancellation, staging, cleanup, and behavior during application-database reconnection have been made more robust.
- **SQLcl MCP:** SQLcl runs with a configurable restrict level through `AIO_SQLCL_MCP_LEVEL`, which defaults to the most restrictive level, `4`. Saved connections can be recreated when needed, and NL2SQL remains unavailable without preventing server startup when SQLcl is not installed.

### Deployment and configuration

- Bare-metal installation and development now use [uv](https://docs.astral.sh/uv/) with a committed lock file. Python 3.11 and 3.12 are supported.
- The Helm chart can provision optional persistent storage for chart-managed SIDB-FREE and ADB-FREE databases. It also supports a fixed client `nodePort` and configurable Ollama service type and port.
- The bundled [SigNoz](https://signoz.io/) chart dependency has been updated.
- Settings import continues to accept legacy database configuration fields, while model reachability and Deep Data Security session state are treated as runtime-only configuration.

### Documentation

- The documentation framework has updated.
- Installation, configuration, client, server, Helm, observability, TLS, infrastructure, and troubleshooting guidance has been reorganized and rewritten.
- A new end-to-end walkthrough and an expanded racing use case cover local models, vector stores, RAG, NL2SQL, and Deep Data Security.

For the complete set of changes, see [`v2.3.2...v2.4.0`](https://github.com/oracle/ai-optimizer/compare/v2.3.2...v2.4.0).
