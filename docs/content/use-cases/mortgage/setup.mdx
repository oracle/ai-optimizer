## Before You Begin

You'll need:

- A configured **AI Optimizer** from the [Walkthrough](../../walkthrough), or an equivalent install with an enabled chat model, an enabled embedding model, and a [database connection](../../client/configuration/databases).
- A chat model with [solid tool use](../../guides/ai-models#choose-a-chat-model-with-reliable-tool-use).
- An [Oracle AI Database connection](../../guides/database.mdx) with rights to create tables and views (the `DB_DEVELOPER_ROLE` granted in the Walkthrough is sufficient).
- The [SQLcl MCP Server](../../guides/sqlcl-mcp-server) configured for **NL2SQL**, pointed at the same database.

The demo assets are under <GitHubSourceLink path="docs/demos/mortgage" type="tree"><code>docs/demos/mortgage/</code></GitHubSourceLink>:

| File                                                                                                    | Purpose                                                                           |
| ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| <GitHubSourceLink path="docs/demos/mortgage/schema.sql"><code>schema.sql</code></GitHubSourceLink>      | Oracle DDL plus eight labelled mortgage applications and a summary view.          |
| <GitHubSourceLink path="docs/demos/mortgage/prompts.json"><code>prompts.json</code></GitHubSourceLink>  | Prompt bundle that tunes NL2SQL, Vector Search, and combined-mode questions.      |
| <GitHubSourceLink path="docs/demos/mortgage/corpus" type="tree"><code>corpus/</code></GitHubSourceLink> | Lending criteria, evidence guidance, and one application pack per mortgagor.      |

## Load the data

Connect to your Oracle AI Database as the user the **AI Optimizer** is configured to use, and run `schema.sql`.

If you are using the database created during the [Walkthrough](../../walkthrough), it runs in a container that cannot access files on your host. Copy the demo directory into the container first, then load the script from inside it:

```bash
podman cp /path/to/mortgage ai-optimizer-db:/tmp/mortgage
podman exec -it ai-optimizer-db sqlplus '<AIO_DB_USERNAME>/<AIO_DB_PASSWORD>@<AIO_DB_DSN>'
```

```sql
@/tmp/mortgage/schema.sql
```

`schema.sql` drops and recreates the mortgage demo tables and view, so run it only in a database or schema you are happy to reset. It seeds eight applications with varied locations, incomes, employment types, expenditure, and LTV profiles.

### Verify the seed

Confirm that the seed contains the mortgage summary view:

```sql
SELECT mortgagor_label, property_location, 
       requested_loan_amount, loan_to_value_pct
  FROM mortgage_application_summary
 ORDER BY mortgagor_label;
```

## Import the prompts

In the **AI Optimizer**, navigate to **Tools** > **Prompts**, select **Upload**, choose `prompts.json`, then select **Upload Prompts**.

This installs:

- A mortgage-review system prompt
- An **NL2SQL** prompt for application and portfolio data
- A **Vector Search** prompt for criteria, evidence guidance, and application packs
- A combined-mode classifier and synthesis prompt for policy-aware questions

See [Prompt Engineering](../../client/tools/prompts) for more on managing prompts.

## Enable models

The demo has been tuned against the on-premises models used in the [Walkthrough](../../walkthrough): [Ollama](https://ollama.com/) `granite4.1:8b` with `mxbai-embed-large`. Other Language Models may work, especially larger ones, but may require some prompt engineering.

See [Model Configuration](../../client/configuration/models) for more on configuring models.

## Embed the corpus

In **Tools** > **Split/Embed**, create one vector store from all files in `corpus/`. Use an alias such as `MORTGAGE_DEMO_DOCS`.
