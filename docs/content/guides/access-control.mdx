AI Optimizer supports multiple users through an embedded authentication gateway.
Streamlit always signs in with `st.login()` against that gateway. The gateway
uses local accounts, GitHub OAuth, or an external OpenID Connect (OIDC)
provider, then assigns one durable AI Optimizer `principal_id` to the user.

The Server uses `principal_id` for working-session ownership and personal
artifacts. The Oracle AI Agent Memory integration uses it as `user_id`. Email
addresses and browser session IDs are profile and transport values, not
ownership values.

## Choose an Authentication Source

| Source | Use it for | Required services |
| --- | --- | --- |
| Local | Developer workstation and test environments | Server, Client, and Oracle CORE database |
| GitHub | Teams that use GitHub accounts | CORE database and a GitHub OAuth application |
| External OIDC | Enterprise identity and lifecycle management | CORE database and an OIDC provider such as OCI IAM Identity Domains |

One source is active for a deployment. Each source produces the same AI
Optimizer principal and authorization roles.

## Local Accounts

Local mode stores individual scrypt password credentials in CORE. It is suited
to development and testing on a developer workstation.

```dotenv
AIO_AUTH_MODE=local
AIO_AUTH_ISSUER=http://127.0.0.1:8765
AIO_AUTH_LOCAL_ADMIN_USERNAME=admin@example.test
AIO_AUTH_LOCAL_ADMIN_PASSWORD=choose-a-password
```

The All-In-One launcher generates and retains the bootstrap password and the
Streamlit client secret when they are unset. The local administrator can create
accounts, reset passwords, disable accounts, and grant `aio.admin` with the
authentication administration CLI:

```bash
uv run python -m server.app.auth_admin add-user \
  --username carol@example.test --display-name Carol
```

## GitHub OAuth

GitHub OAuth is an authorization server, not an OIDC provider. AI Optimizer
bridges GitHub's OAuth callback to its own OIDC gateway, so Streamlit retains
its native `st.login()` flow.

Create a GitHub OAuth application with this authorization callback:

```text
https://auth.example.com/callback
```

Configure the gateway and register the Streamlit redirect URI separately:

```dotenv
AIO_AUTH_MODE=github
AIO_AUTH_ISSUER=https://auth.example.com
AIO_AUTH_WEB_REDIRECT_URI=https://optimizer.example.com/oauth2callback
AIO_AUTH_GITHUB_CLIENT_ID=...
AIO_AUTH_GITHUB_CLIENT_SECRET=...
AIO_AUTH_GITHUB_ALLOWED_USERS=12345678,87654321
AIO_AUTH_GITHUB_ADMIN_USERS=12345678
```

GitHub's numeric user ID is the stable provider subject. Configure
`AIO_AUTH_GITHUB_ALLOWED_ORGANIZATIONS` to permit organization members and
`AIO_AUTH_GITHUB_ADMIN_TEAMS` with `organization/team-slug` values for
administrator mapping. Those policies request GitHub's `read:org` scope.

## External OIDC

External OIDC mode makes the gateway an OIDC relying party upstream and an OIDC
provider to Streamlit downstream. The gateway validates the upstream ID token
and maps its issuer and subject to an AI Optimizer principal.

For OCI IAM Identity Domains, create a confidential application. Add the
gateway callback as an allowed redirect URI, assign the users or groups that
may access the application, and use the identity domain discovery URL as the
issuer.

```dotenv
AIO_AUTH_MODE=oidc
AIO_AUTH_ISSUER=https://auth.example.com
AIO_AUTH_WEB_REDIRECT_URI=https://optimizer.example.com/oauth2callback
AIO_AUTH_OIDC_ISSUER=https://idcs-example.identity.oraclecloud.com
AIO_AUTH_OIDC_CLIENT_ID=...
AIO_AUTH_OIDC_CLIENT_SECRET=...
AIO_AUTH_OIDC_ROLES_CLAIM=groups
AIO_AUTH_OIDC_ALLOWED_CLAIM_VALUES=ai-optimizer-users
AIO_AUTH_ADMIN_CLAIM_VALUES=ai-optimizer-admins
```

The gateway uses authorization code flow with state, nonce, and PKCE. It
validates the upstream token signature, issuer, audience, expiry, nonce, and
subject before a principal is created or updated.

## Authorization and API Access

`aio.user` permits access to the caller's sessions and personal resources.
`aio.admin` permits shared-catalog and authentication administration. Oracle AI
Agent Memory retains the caller's `principal_id` scope for administrator
requests.

The gateway issues a signed ID token to Streamlit and an opaque access token to
REST and MCP clients. The Server resolves each access token against CORE and
loads the principal's current roles and active status. Logout revokes the
gateway session and its API tokens.

`X-AIO-Session` selects a working session after authentication. The Server
binds that session to the authenticated `principal_id` and rejects use by a
different principal.

## Shared API-Key Deployments

Without CORE, leave `AIO_AUTH_MODE` unset and use `AIO_API_KEY`. This is a
single-principal compatibility mode. It cannot provide end-user isolation or
enable Oracle AI Agent Memory.

`AIO_CLIENT_PASSWORD` is retired and rejected at Server startup.
